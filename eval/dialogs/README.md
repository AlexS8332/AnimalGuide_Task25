# Длинные сценарии диалога

Два разговора по 14–15 реплик человека со справочной по базе знаний (пресет
`rag`: механизмы `rag`, `rag.filter`, `rag.rewrite`, `rag.cite`, `task`). Они
проверяют, что ассистент не теряет цель разговора и на каждый вопрос отвечает
с источниками.

| Файл | Сценарий | Реплик | Что испытывает |
|---|---|---|---|
| `a.json` | Доклад для школьников о кошках Азии | 15 | цель и три ограничения в первой реплике («простыми словами», «без латыни», «не больше 5 предложений»), термин «барс» = ирбис, местоимения, голое название, уход в сторону (полосатая гиена) и возврат, сравнение с видом, который давно вышел из окна; контроль цели на 5-й, 10-й и 15-й репликах |
| `b.json` | Проверка систематики малых панд и куньих по MDD | 14 | уровень специалиста, вопросы по MDD v2.5, сравнение «харза и соболь по массе», смена ограничения посередине («теперь с латынью и статусами МСОП»), вопрос вне базы (фосса), местоимение после вопроса вне базы; контроль цели на 5-й, 10-й и 14-й |

## Прогон

Приложение должно быть запущено (ключ модели — в окружении, база знаний собрана):

```
go run . -preset rag
go run ./cmd/kb chat -script eval/dialogs/a.json
go run ./cmd/kb chat -script eval/dialogs/b.json -json > b.jsonl
```

`kb chat` — клиент REST приложения: создаёт новый диалог с пресетом сценария,
отправляет реплики по одной, ждёт конца хода по потоку событий и берёт итог
хода из истории диалога. По каждому ходу печатает ответ, источники, цитаты,
правки памяти задачи, цену и строку проверок (`[+]` пройдена, `[-]` нет,
`[~]` не определить), в конце — итог и список провалов. Код выхода 1 — хоть
одна проверка не пройдена. `-json` — по строке JSON на ход в stdout (ход из
истории целиком, с журналом событий, и проверки), последняя строка — итог.

Без `-script` — интерактивный чат: `/new` — новый диалог с пресетом,
`/task` — память задачи, `/quit` — выход.

## Формат

```json
{
  "schema": 1,
  "id": "A",
  "title": "…",
  "preset": "rag",
  "goal": {"text": "цель одной фразой", "keywords": ["доклад|сообщени", "школ|дет", "кош|кот", "ази"]},
  "rules": [
    {"kind": "no_latin", "from": 1, "to": 6},
    {"kind": "max_sentences", "n": 5, "from": 1},
    {"kind": "iucn", "turns": [7, 8]}
  ],
  "turns": [
    {"text": "реплика человека", "docs": ["manul"], "marks": ["goal_set"], "note": "что в корпусе отвечает"},
    {"text": "сравни харзу и соболя", "docs": ["yellow-throated-marten", "sable"]},
    {"text": "какой статус у малой панды", "docs": ["mdd-carnivora|red-panda"]},
    {"text": "вопрос вне базы", "unknown": true, "marks": ["unknown"]},
    {"text": "Напомни, какая у нас цель и что мы решили.", "marks": ["goal"]}
  ]
}
```

- `turns` — 10–15 реплик человека по порядку.
- `docs` — doc_id корпуса, каждый должен быть среди источников ответа
  (doc_id источника — начало chunk_id до первой «/»); альтернативы — через
  `|`. Ожидаемые doc_id сверены с текстом корпуса: ответ там есть (`note`
  говорит, что именно).
- `unknown: true` — вопроса нет в базе: ждём «не знаю» с уточнением, `docs`
  нет.
- `marks` — что реплика испытывает: `goal` (контрольная: ответ называет
  цель), `goal_set`, `constraint`, `term`, `pronoun`, `offtopic`, `return`,
  `bare`, `compare`, `unknown`. Проверку включает только `goal`.
- `goal.keywords` — группы ключевых слов цели; каждая группа должна найтись
  в ответе контрольной реплики (по началу слова, без учёта регистра и ё).
- `rules` — ограничения ответа на ходах `from`..`to` (`to` нет — до конца)
  или только на ходах `turns`: `no_latin` (нет латинского бинома),
  `latin` (есть), `max_sentences` с `n`, `iucn` (назван статус МСОП).
  «Простыми словами» кодом не проверить — это дело судьи.

## Проверки

Пакет `internal/dialogs`, функция `CheckTurn` по тому, что ход дал
(`Observed`: текст ответа и итог `rag.cite` из итогов хода):

| Проверка | Пройдена, если |
|---|---|
| `reply` | ход завершился ответом |
| `sources` | вопрос по базе — ответ `answered` со списком источников; вопрос вне базы — `unknown`; контрольная реплика — ответ по памяти задачи (`meta`) или по базе с источниками |
| `docs` | каждый ожидаемый doc_id среди источников |
| `no_latin`, `latin`, `max_sentences`, `iucn` | ограничение соблюдено в самом ответе — без «Источников» и цитат (латынь в цитате из MDD — не нарушение «без латыни»); требования «есть латынь», «есть статус» на «не знаю» и на контрольной реплике не определить |
| `goal` | контрольная реплика: все группы ключевых слов цели в ответе |

Проверки — признаки текста, а не судья: они ошибаются в обе стороны, поэтому
вывод всегда показывает сами ответы рядом с отметками. `dialogs.Play` гоняет
сценарий поверх любого `Asker` (REST у `kb chat`, менеджер ходов у стенда).
